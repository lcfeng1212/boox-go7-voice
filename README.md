# BOOX Go 7 中文語音翻頁

版本 0.3.0｜Android 13｜完全離線

在 BOOX Go 7 上看書時，說「下一頁」或「上一頁」就能翻頁，不用伸手碰螢幕或按鍵。主要為「起點讀書」設計，其他用左右滑動翻頁的閱讀 App 也可使用。

---

## 簡介

一般 Android 語音控制方案（例如 Tasker 加 AutoVoice）需要多個付費 App、要連網，設定也繁瑣。本 App 把整套流程做成單一 App：

- **離線辨識**：內建 Vosk 小型中文語音模型，全部在裝置上運算。App 不要求網路權限，聲音不會上傳。
- **只做翻頁**：透過 Android 無障礙服務模擬左右滑動。服務設定為不讀取螢幕內容，不會取得其他 App 的文字。
- **針對電子紙**：介面是高對比黑白，狀態文字只在內容變動時才重繪，減少螢幕刷新。

適合躺著看書、吃東西、手上拿著東西，或單純不想一直按的時候。

## 運作原理

```
麥克風 ──▶ Vosk 離線中文辨識 ──▶ 指令比對 ──▶ 無障礙手勢 ──▶ 閱讀 App 翻頁
(前景服務)    (只比對翻頁指令)     (防重複觸發)    (左右滑動)
```

1. 「離線聆聽」以前景服務持續收音，通知列會常駐一則通知。
2. 辨識結果只要符合翻頁指令，就交給無障礙服務。
3. 無障礙服務在螢幕中間高度做一次水平滑動：
   - 下一頁：從右往左滑。
   - 上一頁：從左往右滑。
4. 兩次翻頁至少間隔約 0.9 秒，避免一句話翻兩頁。

## 系統需求

| 項目 | 需求 |
|---|---|
| 裝置 | BOOX Go 7（arm64）；其他 Android 9 以上、arm64 架構的裝置理論上可用，但未測試 |
| 系統 | 開發目標為 Android 13 |
| 儲存空間 | APK 約 63 MB；第一次啟動會再把語音模型解壓到 App 私有空間，約 70 MB |

## 下載 APK

1. 打開本儲存庫的 **Actions** 分頁 → **BOOX Android APK build**。
2. 點最新一筆綠色勾勾（成功）的執行紀錄。
3. 在頁面最下方的 **Artifacts** 下載 `BOOX-Go7-Chinese-VoicePage-APK`（ZIP 檔，需登入 GitHub）。
4. 解壓縮後取得 `app-debug.apk`。

> Artifacts 有保存期限，過期後要重新觸發一次編譯：Actions → BOOX Android APK build → Run workflow。

## 安裝與首次設定

1. **安裝 APK**：把 `app-debug.apk` 複製到 BOOX Go 7，點開安裝；系統詢問時允許「安裝未知來源 App」。
2. **啟用無障礙服務**：開啟本 App，按「① 開啟無障礙設定」，找到「BOOX 語音翻頁手勢」並啟用。
   - Android 13 若顯示「**受限制的設定**」而無法啟用：到「設定 → 應用程式 → BOOX 中文語音翻頁」的 App 資訊頁，點右上角選單「允許受限制的設定」，再回來啟用。
3. **開始聆聽**：回到本 App，按「② 開始離線聆聽」，允許麥克風權限。第一次會先解壓語音模型，狀態顯示「正在載入離線中文模型」，需要稍等。
4. **確認狀態**：App 畫面顯示「無障礙：已啟用」、「麥克風：運作中」，狀態為「離線聆聽中」，即設定完成。
5. **BOOX 背景設定**：在 BOOX 的 App 最佳化設定中，允許本 App 背景執行、不要凍結，否則鎖屏或切換 App 後可能被系統停止。

## 使用方式

1. 完成上述設定後，切回起點讀書並打開書本。
2. 對著裝置說指令，例如「下一頁」。
3. 要停止時，下拉通知列按「停止」，或回本 App 按「停止聆聽」。

### 指令表

| 動作 | 可說的指令 |
|---|---|
| 下一頁 | 下一頁、下頁、翻頁、翻下一頁、往下翻、小書下一頁 |
| 上一頁 | 上一頁、上頁、翻上一頁、往上翻、小書上一頁 |

- 指令請單獨、清楚地講。一口氣連講兩次（例如「下一頁下一頁」）不會觸發，要翻兩頁請分開講。
- 限定指令模式下，指令前後若有被判定為未知的雜音，不影響比對。

### 測試按鈕

App 內的「測試下一頁（左滑）」、「測試上一頁（右滑）」會直接送出一次滑動手勢，用來確認無障礙服務有沒有作用。手勢會作用在當下的畫面上，也就是本 App 自己，所以畫面不會有明顯變化；只要提示「已送出手勢」就代表正常。

## 兩種辨識模式

App 內可勾選「限定指令模式」，預設為開啟。

| | 限定指令模式（預設） | 一般模式 |
|---|---|---|
| 辨識範圍 | 只比對翻頁指令，其他聲音一律視為未知 | 完整中文模型，什麼話都會轉成文字再比對 |
| 誤判 | 較少 | 較多 |
| 耗電／運算量 | 較低 | 較高 |
| 反應速度 | 較快：話還沒講完、辨識穩定時就翻頁 | 較慢：要等講完、停頓後才翻頁 |
| 何時改用 | — | 限定模式聽不到你的指令，或旁人說話也一直誤翻時，切換比較看看 |

切換模式後，要先按「停止聆聽」再重新「開始離線聆聽」才會生效。

## 隱私與權限

| 權限 | 用途 |
|---|---|
| 麥克風（RECORD_AUDIO） | 收音辨識翻頁指令。聲音只在裝置上處理，不會儲存或上傳 |
| 前景服務（FOREGROUND_SERVICE、FOREGROUND_SERVICE_MICROPHONE） | 切到閱讀 App 後仍可持續收音 |
| 通知（POST_NOTIFICATIONS） | 顯示「正在聆聽」常駐通知與停止按鈕 |
| 無障礙服務 | 只用來模擬滑動手勢；設定為不讀取視窗內容（`canRetrieveWindowContent=false`） |

App 不要求網路權限（INTERNET）。每次編譯時，CI 都會自動檢查 APK 的權限清單，確認沒有網路權限。

## 疑難排解

| 狀況 | 可能原因與處理 |
|---|---|
| 按「開始離線聆聽」跳出「請先啟用無障礙手勢」 | 無障礙服務尚未啟用，請先完成設定第 2 步 |
| 無障礙服務無法啟用、顯示「受限制的設定」 | 見設定第 2 步，先在 App 資訊頁允許受限制的設定 |
| 狀態顯示「無障礙手勢未成功」 | 無障礙服務被系統關閉。請到無障礙設定重新啟用 |
| 說了指令沒反應 | 先看 App 狀態是否為「離線聆聽中」；說話距離近一點、語速放慢；仍不行就切換成一般模式比較 |
| 旁人說話或看影片時誤翻頁 | 確認已開啟限定指令模式；仍誤翻則暫停聆聽 |
| 用一陣子後自動停止 | BOOX 背景限制或休眠中斷了服務。請完成設定第 5 步；必要時把 BOOX 自動休眠時間調長 |
| 第一次開始聆聽很久才就緒 | 正在解壓語音模型，只有第一次會這樣 |
| 狀態顯示「辨識逾時，正在重新啟動」 | 收音中斷後 App 會自動重啟辨識，通常幾秒內恢復 |

## 已知限制

- 持續收音會增加耗電，不看書時建議停止聆聽。
- 只用聲音翻頁、完全不碰螢幕時，BOOX 是否會自動休眠，尚未在實機上確認。
- 翻頁是靠模擬滑動，閱讀 App 若改成其他翻頁方式（例如只支援點擊），可能需要調整手勢。
- 目前只在 Android 13 模擬器做過安裝與啟動測試；語音辨識率與起點讀書的實際翻頁效果，須以 BOOX Go 7 實機為準。

## 開發與編譯

### 專案結構

```
app/src/main/java/tw/boox/voicepage/
├── MainActivity.java              主畫面：設定步驟、模式切換、狀態顯示
├── OfflineListeningService.java   前景服務：收音、Vosk 辨識、錯誤自動重啟
├── SwipeAccessibilityService.java 無障礙服務：送出左右滑動手勢
├── CommandEngine.java             指令清單、文字正規化、防重複觸發
├── GestureGeometry.java           依螢幕尺寸計算滑動座標
├── ModelAssets.java               首次啟動時解壓語音模型
├── RestartPolicy.java             辨識失敗時的退避重試
└── ListeningHealth.java           偵測辨識停止回應
scripts/
├── prepare_model.py               下載官方 Vosk 中文模型並檢查 ZIP 安全性
├── check_grammar_vocab.py         確認每個指令詞都在模型詞彙表內
└── emulator_smoke.sh              模擬器安裝與啟動測試
tests/                             指令邏輯單元測試
```

### 本機編譯

需要 JDK 17、Android SDK（platform 35、build-tools 35.0.0）、Gradle 8.9。

```bash
bash tests/run_tests.sh                               # 單元測試
python3 scripts/prepare_model.py                      # 下載語音模型
bash tests/run_tests.sh app/src/main/assets/model-cn  # 測試並檢查指令詞彙
gradle assembleDebug                                  # 產出 app/build/outputs/apk/debug/app-debug.apk
```

### 新增指令

1. 在 `CommandEngine.GRAMMAR_PHRASES` 加入辨識用的詞組。要用**簡體、以空格分詞**，而且每個詞都必須在模型詞彙表內。例如「上一页」不是模型裡的詞，要寫成「上 一页」。
2. 在 `CommandEngine.parse` 加入對應的繁體寫法。
3. 執行 `bash tests/run_tests.sh app/src/main/assets/model-cn`。詞彙表裡找不到的詞會列為 `MISSING`。

### 自動編譯（GitHub Actions）

每次 push 到 `main` 會自動執行 `.github/workflows/build-apk.yml`：

1. **build**：單元測試 → 下載（或從快取還原）語音模型 → 檢查指令詞彙 → 編譯 APK → 檢查權限與內容 → 上傳 Artifact。
2. **emulator-smoke**：在 Android 13 模擬器安裝 APK、啟動主畫面，並確認兩個服務都有宣告。

整個流程約 4 分鐘。
